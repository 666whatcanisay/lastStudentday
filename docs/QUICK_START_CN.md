# 30 分钟快速理解：先会用，再懂原理

## 0–5 分钟：认清它要解决什么

一张票据原来只是“图片”。系统先读出字，再找编号、日期、金额等字段；你核对以后，字段才能更可靠地用来统计和导出。问答则帮你在这些资料里找证据。

四个板块可以这样记：文档管理是加工台，统计是汇总台，问答是查资料的助手，数据管理是管理员的保险柜。

首次上手不必上传新文件，也不必改正式数据。登录使用项目负责人提供的口令；**一个口令登录后即完整管理员**，没有单独的访客口令。

## 5–15 分钟：看一份文档的完整生命周期

1. 打开文档管理，搜索“信息技术服务费发票”，选择桌面的“详情”或手机卡片的“查看”。这是合成演示样本，不是真实经营记录。
2. 看原件，再看字段：不含税金额 54,464.66，税额 3,267.88，价税合计 57,732.54。它们是不同概念，不能拿第一行明细金额当总额。
3. 原件只写“日期”，因此“开票日期”留空；“元”缺少足够币种证据，所以币种留空。这不是识别失败，而是避免偷换字段含义。
4. 打开校对界面，只查看不用保存：桌面原件与字段并排，手机先后查看原件、字段和全文。保存只保存结果；“保存并标记已校对”是另一种明确选择。
5. 查看版本历史。原始 OCR 与旧字段快照仍保留；人工修正形成新有效版本，不把过去抹掉。
6. 导出单份 PDF，检查报告的版本号与页面内容对应；返回列表，工具栏**常驻**「导出 PDF / 导出 Excel」，勾选文档后按钮可用，可导出 Excel 或 PDF ZIP。

练习编辑、重识别、删除和恢复请在隔离数据副本做。重识别会产生新版本；删除进入回收站，永久删除不能撤销。

## 15–20 分钟：理解统计为什么有空项

保守整理后的基线是 26 份有效文档：5 发票、5 合同、16 其他，均已完成本轮来源核对。11 份缺少可确认的业务日期；10 份发票/合同都未确认币种。以后用户操作会改变这些数量，不要把基线数字当成永恒常量。

先看数据质量提示，再看类型与数量图表。金额虽然已确认，不同币种不能混算，币种未知也不能假装人民币总额。日期筛选使用业务日期，不用上传时间顶替。

点击图表时，打开的是同一组筛选条件下的明细。你应该能从汇总追到来源，而不是只看一张漂亮图。

## 20–25 分钟：理解问答是“先查证据，再回答”

限定在合成发票样本，尝试问“信息技术服务费发票的价税合计是多少”。展开检索过程，注意关键词、向量两路结果以及最后引用的原文。

关键词像按原词查目录，向量像按意思找相近内容，两路融合能互相补充。但没有查到资料就应该说明缺证据，不能编一个金额。

配置云端模型后，发送问题会把选中的相关片段传给模型服务。没有 Key、网络失败或额度不足时，项目可以回到检索证据模式；不要把检索片段称为大模型已经生成了完整答案。本轮不主动调用真实付费云端。

## 25–30 分钟：掌握上台必须说清的五句话

1. 我们做的是文档处理工作台，不只是 OCR 上传页面。
2. OCR 负责把图变成字，字段规则负责从字里找明确的信息，人工校对负责确认业务事实。
3. 统计、导出、问答都跟随当前有效版本，修改时有版本冲突保护。
4. 本地核心功能可在 CPU 上运行；云端模型只参与可选的生成式问答。
5. 未知字段留空、币种不混算、引用可回查、修改可追溯，比把表格强行填满更重要。

如果能用自己的话讲完这五句，再对照技术流程图解释每个箭头，你就已经掌握了项目主线。
